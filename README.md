## 1. สรุปภาพรวมใน 1 นาที (Overview)

เวลาคนทั่วไปต้องการซื้อคอมพิวเตอร์หรือแล็ปท็อป **มักจำชื่อรุ่นเป๊ะ ๆ (SKU) ไม่ได้** แต่จะบอกความต้องการเป็นภาษาคน เช่น:

> 💬 *"อยากได้โน้ตบุ๊กไว้เขียนโปรแกรม งบ 30,000"*  
> 💬 *"Gaming Laptop RTX 4060 ราคาไม่เกิน 40000"*

```
[ ระบบค้นหา E-Commerce ทั่วไป ]            [ ระบบ ISE (Intelligent Search Engine) ]
─────────────────────────────────          ─────────────────────────────────────────
ผู้ใช้ต้องระบุชื่อรุ่น/สเปกที่ถูกต้อง         ผู้ใช้พิมพ์ "ความต้องการ + งบประมาณ" ตามจริง
       ↓                                          ↓
ค้นหาแบบจับคู่คำตรงๆ (Exact Match)          แยกแยะเงื่อนไข (Category, Budget, Hardware, Use Case)
       ↓                                          ↓
กรองราคาแบบทวิภาค (เกิน 1 บาทตัดทิ้ง)        ใช้ Inverted Index + Soft Budget Window (+15%)
       ↓                                          ↓
เรียงตามราคาต่ำสุด (ได้เครื่องสเปกต่ำ)         คำนวณคะแนนถ่วงน้ำหนัก 4 มิติ (Multi-Criteria)
       ↓                                          ↓
ไม่บอกเหตุผลว่าทำไมถึงแนะนำ                 แสดงคะแนนละเอียด พร้อมอธิบายเหตุผลภาษาไทย
```

## 2. ปัญหาจริงที่ระบบนี้เข้ามาแก้ (The Problem)

```
                       ความล้มเหลวของการค้นหาแบบเดิม (Traditional Search Failure)
                       ──────────────────────────────────────────────────────────

  ผู้ใช้พิมพ์: "โน้ตบุ๊กสำหรับเขียนโปรแกรม งบไม่เกิน 30000"
       │
       ├──> ❌ ปัญหา 1: ไม่พบสินค้า (Keyword Mismatch)
       │    ชื่อสินค้าในตลาดตั้งว่า "ASUS Vivobook 16" ไม่มีคำว่า "เขียนโปรแกรม" อยู่ในชื่อ
       │
       ├──> ❌ ปัญหา 2: กรองราคาแข็งเกินไป (Binary Filter Drop)
       │    โน้ตบุ๊กราคา 30,900 บาท ที่ได้ RAM 16GB และ CPU แรงกว่า 2 เท่า ถูกตัดทิ้งทันทีเพราะเกินงบ 900 บาท
       │
       ├──> ❌ ปัญหา 3: จัดเรียงด้วยราคาต่ำสุด (Lowest Price Bias)
       │    ระบบนำเครื่องราคา 14,900 บาท (CPU 4 คอร์, RAM 8GB) มาเป็นอันดับ 1 ซึ่งทำงานเขียนโค้ดจริงไม่ได้
       │
       └──> ❌ ปัญหา 4: ไม่มีคำอธิบาย (Zero Explainability)
            ผู้ใช้ไม่รู้ว่าเครื่องไหนเหมาะกับตนเอง ต้องเปิดเทียบสเปกเองทีละหลายสิบแท็บ
```

ISE แบ่งการทำงานออกเป็น **5 ขั้นตอนที่เชื่อมโยงกันอย่างเป็นระบบ**:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                 1. USER QUERY INPUT                                    │

│                        2. QUERY PROCESSING & UNDERSTANDING                             │
│  - Tokenize & Clean ข้อความ                                                            │
│  - Rule-Based Intent Parser สกัดโครงสร้างความต้องการ:                                  │
│    • หมวดหมู่ (Category): Gaming Laptop                                               │
│    • การ์ดจอ (GPU Target): RTX 4060                                                   │
│    • เพดานงบประมาณ (Budget Max): ≤ 40,000 บาท                                         │
│    • การใช้งาน (Use Case): Gaming                                                      │

│  - กรองเฉพาะหมวดหมู่ Gaming Laptop ที่ติดตั้งชิป RTX 4060                                │

                                            │

┌────────────────────────────────────────────────────────────────────────────────────────┐
│                         5. EXPLAINABLE RANKING & PRESENTATION                          │
```

## 4. เจาะลึก 5 อัลกอริทึมที่ใช้จริงในโค้ด (Algorithms Used)

ทุกอัลกอริทึมในโปรเจกต์นี้ถูกเลือกขึ้นมาเพื่อแก้ปัญหาเฉพาะจุดใน Pipeline ไม่ได้ใส่มาเพื่อให้ดูซับซ้อน:

```
    [จัดระเบียบข้อความ]              [เข้าใจความต้องการ]               [คัดกรองตัวเลือก]
┌─────────────────────────┐     ┌─────────────────────────┐     ┌─────────────────────────┐
│ 4.1 Query Processing    │ ──> │ 4.2 Query Understanding │ ──> │ 4.3 Candidate Retrieval │
└─────────────────────────┘     └─────────────────────────┘     └─────────────────────────┘
                                                                             │
    [อธิบายเหตุผลโปร่งใส]             [ตัดสินความเหมาะสมรอบด้าน]                  │
┌─────────────────────────┐     ┌─────────────────────────┐                  ▼
│ 4.5 Explainable Ranking │ <── │ 4.4 Weighted Ranking    │ <────────────────┘
└─────────────────────────┘     └─────────────────────────┘
```

---

### 4.1 Query Processing & Tokenization (`js/engine/queryParser.js`)
- **หน้าที่:** จัดการข้อความที่พิมพ์เข้ามาไม่เป็นระเบียบให้อยู่ในรูปมาตรฐาน (Normalized Tokens)
- **การทำงาน:**
  - แปลงข้อความทั้งหมดเป็นตัวพิมพ์เล็ก (Lowercase)
  - แปลงหน่วยตัวเลขแบบย่อ เช่น `"40k"` $\to 40,000$, `"3 หมื่น"` $\to 30,000$, ตัดเครื่องหมายจุลภาค `"30,000"` $\to 30,000$
  - แยกคำ (Tokenize) โดยยังคงรักษาคำศัพท์สเปกสำคัญไว้ เช่น `rtx`, `4060`, `16gb`, `144hz`, `27"`

---

### 4.2 Rule-Based Query Understanding / Intent Parsing (`js/engine/queryParser.js`)
- **หน้าที่:** สกัดความต้องการของผู้ใช้ให้กลายเป็นโครงสร้างข้อมูล (Structured Intent)
- **การทำงาน (ใช้ Rule-Based & Regex ไม่ใช่โมเดล AI):**
  - **Category Parser:** ตรวจจับคำว่า `"โน้ตบุ๊ก"`, `"gaming laptop"`, `"จอ"`, `"การ์ดจอ"`, `"cpu"`, `"ssd"`
  - **Budget Bounds:** ตรวจจับขอบเขตราคา เช่น `"งบไม่เกิน 30000"`, `"ราคาไม่เกิน 40000"`, `"20000 ถึง 30000"`
  - **Hardware Extraction:** สกัดชิป GPU (`RTX 4060`), แรม (`16GB`), ขนาดจอ (`27"`), อัตรารีเฟรช (`144Hz`)
  - **Use Case Mapping:** แปลงคำค้นหาเป็นโดเมนงาน:
    - `"เขียนโปรแกรม"`, `"coding"`, `"developer"` $\to$ โดเมน **Programming**
    - `"เล่นเกม"`, `"gaming"`, `"esports"` $\to$ โดเมน **Gaming**
    - `"บางเบา"`, `"แบตอึด"`, `"พกพา"` $\to$ โดเมน **Thin & Light**

```json
// ตัวอย่าง Output ของ Query Understanding ที่ระบบสร้างขึ้นจริง
{
  "category": "Gaming Laptop",
  "budget": { "min": null, "max": 40000, "target": 40000 },
  "specs": { "gpu": "RTX 4060", "ram": null, "displaySize": null, "refreshRate": null },
  "useCase": "Gaming",
  "priority": "ประสิทธิภาพชิปกราฟิกและการระบายความร้อน"
}
```

---

### 4.3 Candidate Retrieval & Soft Filtering (`js/engine/retrieval.js`)
- **หน้าที่:** ลดขอบเขตการค้นหา ดึงเฉพาะสินค้าที่มีโอกาสตรงเงื่อนไขเข้าสู่รอบคำนวณคะแนน
- **โครงสร้างข้อมูล:** **In-Memory Inverted Index** (`Map<token, Set<productId>>`) จับคู่คำสำคัญกับรหัสสินค้า
- **หลักการ Soft-Budget Window (+15%):**
  - หากตั้งงบไว้ 30,000 บาท ระบบจะอนุโลมให้สินค้าที่มีราคาถึง **34,500 บาท** ผ่านเข้ารอบ Ranking ได้
  - **เหตุผล:** เพื่อเปิดโอกาสให้สินค้าที่เกินงบเล็กน้อยแต่ได้สเปกคุ้มค่ากว่ามาก ถูกนำมาคิดคะแนนและหักลบอย่างเป็นธรรมทางคณิตศาสตร์ ดีกว่าตัดทิ้งแบบ Binary Hard Filter

---

### 4.4 Multi-Criteria Weighted Ranking (`js/engine/ranking.js`)
- **หน้าที่:** อัลกอริทึมหลักในการตัดสินอันดับ โดยชั่งน้ำหนักปัจจัยรอบด้านพร้อมกัน

$$\mathbf{FinalScore} = (S_{\text{rel}} \times 0.30) + (S_{\text{bud}} \times 0.25) + (S_{\text{spec}} \times 0.25) + (S_{\text{use}} \times 0.20)$$

```
  คะแนนความตรงคำค้น (Relevance) ──[ 30% ]──┐
  คะแนนความคุ้มงบ (Budget)     ──[ 25% ]──┼──> [ FINAL MATCH SCORE (0 - 100) ]
  คะแนนสเปกฮาร์ดแวร์ (Specs)    ──[ 25% ]──┤
  คะแนนเหมาะกับงาน (Use Case)  ──[ 20% ]──┘
```

| มิติการประเมิน | น้ำหนัก | หลักการให้คะแนน (Scale 0 - 100) |
| :--- | :---: | :--- |
| **1. Relevance ($S_{\text{rel}}$)** | **30%** | ตรงหมวดหมู่หลัก ($+35$), แบรนด์ตรง ($+15$), จำนวนคำค้นตรงกับ Inverted Index ($+5$ ถึง $+20$) |
| **2. Budget ($S_{\text{bud}}$)** | **25%** | **อยู่ในงบ:** ได้ $92-100$ คะแนนตามอัตราส่วนความคุ้มค่า<br>**เกินงบ:** หักคะแนนตามเส้นโค้งความชัน $100 - (\text{overflow} \times 350)$ (เกิน 10% เหลือ 65 คะแนน, เกิน 28% เหลือ 0) |
| **3. Specifications ($S_{\text{spec}}$)** | **25%** | วัดความตรงของฮาร์ดแวร์ที่ขอ เช่น ได้ชิป RTX 4060 ตรงรุ่นได้ 100, ได้รุ่นต่ำกว่าอย่าง 4050 ได้ 65 |
| **4. Use Case ($S_{\text{use}}$)** | **20%** | วัดคะแนนความพร้อมเฉพาะด้าน เช่น งาน Programming ดู Multi-core CPU + RAM, งานพกพาดูน้ำหนักเครื่องและแบตเตอรี่ |

#### ทำไม Weighted Ranking จึงแก้ปัญหาได้จริง?
ลองเปรียบเทียบการจัดอันดับในงบ **30,000 บาท** สำหรับงาน **เขียนโปรแกรม**:
- **เครื่องราคาถูก 14,900 บาท (CPU 4 คอร์, RAM 8GB):** อยู่ในงบ ($S_{\text{bud}} = 85$) แต่สเปกต่ำ ($S_{\text{spec}} = 55$) และไม่เหมาะกับงาน ($S_{\text{use}} = 55$) $\longrightarrow$ **คะแนนรวมตกไปอยู่ที่ 72 คะแนน (อันดับท้าย)**
- **เครื่องราคา 28,900 บาท (i5 12 คอร์, RAM 16GB, จอ OLED):** คุ้มค่างบประมาณ ($S_{\text{bud}} = 100$), สเปกสูง ($S_{\text{spec}} = 92$), เหมาะกับงานเขียนโค้ด ($S_{\text{use}} = 92$) $\longrightarrow$ **คะแนนรวมได้ 95 คะแนน (อันดับ 1 Best Match)**

---

### 4.5 Explainable Ranking & Reasoning (`js/engine/explainer.js`)
- **หน้าที่:** เปลี่ยนตัวเลขคะแนนที่เข้าใจยาก ให้เป็นเหตุผลภาษาไทยที่อ่านแล้วเข้าใจทันที
- **การทำงาน:** สังเคราะห์ข้อความจาก **สัญญาณคะแนนจริง (Signal-to-Text)** ที่ชนะในรอบ Ranking:

```
[ สัญญาณที่ชนะการจัดอันดับ ]                   [ บทวิเคราะห์ภาษาไทยที่แสดงให้ผู้ใช้เห็น ]
  • ราคา ฿28,900 <= งบ ฿30,000   ──────>   "อยู่ในงบประมาณที่ตั้งไว้ (฿28,900 จากงบ ฿30,000)"
  • CPU i5-13500H (12 Cores)      ──────>   "ซีพียู 12 คอร์ เหมาะสำหรับการคอมไพล์โค้ดและรัน Docker"
  • RAM 16GB DDR5                 ──────>   "มีหน่วยความจำ RAM 16GB รองรับงาน Multitasking ได้ดี"
  • หน้าจอ 45% NTSC               ──────>   "ข้อควรพิจารณา: หน้าจอสีมาตรฐานทั่วไป ไม่เหมาะกับงานแต่งสีมืออาชีพ"
```

## 5. ตัวอย่างการทำงานจริงทีละขั้นตอน (Step-by-Step Example)

### ค้นหา: `"Gaming Laptop RTX 4060 ราคาไม่เกิน 40000"`

```
[ขั้นตอนที่ 1: ตีความเจตนา]
  - หมวด: Gaming Laptop | การ์ดจอ: RTX 4060 | งบ: ≤ 40,000 บาท | ใช้งาน: เล่นเกม

[ขั้นตอนที่ 2: ดึง Candidate เข้าสู่รอบคัดเลือก]
  - กรองสินค้าจนเหลือ Gaming Laptop ที่ใช้การ์ดจอ RTX 4060 ได้ทั้งหมด 4 รุ่น

[ขั้นตอนที่ 3: คำนวณคะแนน Multi-Criteria Weighted Ranking]
```

| รุ่นสินค้า | ราคา | ตรงคำค้น (30%) | ความคุ้มงบ (25%) | สเปกฮาร์ดแวร์ (25%) | เหมาะกับงาน (20%) | คะแนนรวมสุทธิ | อันดับผลลัพธ์ |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **Lenovo LOQ 15** (i5-HX, RTX 4060 105W) | ฿37,900 | 100 | 100 | 100 | 92 | **98 / 100** | 🏆 **อันดับ 1 (Best Match)** |
| **HP Victus 16** (Ryzen 5, RTX 4060 120W) | ฿38,900 | 100 | 100 | 100 | 91 | **98 / 100** | **อันดับ 2** |
| **Acer Nitro V 15** (i5, RTX 4060 75W) | ฿34,900 | 100 | 100 | 100 | 89 | **97 / 100** | **อันดับ 3** |
| **ASUS TUF A15** (Ryzen 7, RTX 4060 140W) | ฿44,900 | 90 | **57** *(เกินงบ 12%)* | 100 | 95 | **85 / 100** | **อันดับ 4** |


## 7. ระบบต้นแบบ (Prototype) vs ระบบจริงในอนาคต (Production System)

โครงการนี้พัฒนาในระดับ **Capstone Prototype** เพื่อพิสูจน์แนวคิดการจัดอันดับ นี่คือความแตกต่างระหว่างสิ่งที่มีอยู่จริงในโค้ดปัจจุบัน กับสิ่งที่จะพัฒนาต่อในระบบ Production:

| องค์ประกอบ | สิ่งที่มีจริงใน Prototype ปัจจุบัน | แนวทางการพัฒนาต่อเป็น Production ในอนาคต |
| :--- | :--- | :--- |
| **สถาปัตยกรรม** | Client-Side SPA (Vanilla HTML5 / CSS3 / ES6) | Decoupled Web App (Next.js) + Backend API Service (Go / Node.js) |
| **การจัดเก็บข้อมูล** | In-Memory JavaScript Objects (60+ สินค้าไอทีจริง) | Relational Database (PostgreSQL) พร้อมตารางสเปกแยกตามหมวด |
| **การค้นหาและดัชนี** | In-Memory Inverted Token Index (`Map`) | Dedicated Search Engine เช่น **Elasticsearch / OpenSearch (BM25)** |
| **การเข้าใจคำค้นหา** | Deterministic Regex & Rule-Based Intent Parser | Hybrid NLP: Rule-based + Statistical Named Entity Recognition (NER) |
| **การอัปเดตราคา** | ชุดข้อมูลมาตรฐานโรงงานประเทศไทย | Background Web Scraping / Retailer API Sync อัปเดตราคาแบบ Real-time |
| **การแคชข้อมูล** | Browser Client State | Distributed Caching ด้วย **Redis** |

## 8. การทดสอบและประเมินผลเชิงประจักษ์ (Benchmark & Evaluation)

ใน Prototype ได้ติดตั้งระบบ **Regression Test Suite** เพื่อทดสอบอัลกอริทึมกับ **6 สถานการณ์การค้นหาจริง**:
1. *"โน้ตบุ๊กสำหรับเขียนโปรแกรม งบไม่เกิน 30000"*
2. *"Gaming Laptop RTX 4060 ราคาไม่เกิน 40000"*
3. *"จอ 27 นิ้ว 144Hz"*
4. *"SSD 1TB สำหรับ Gaming"*
5. *"CPU สำหรับทำงาน AI"*
6. *"โน้ตบุ๊กบางเบา แบตอึด สำหรับทำงาน"*

### ผลลัพธ์เปรียบเทียบกับ Baseline Search (ค้นตามคีย์เวิร์ด + เรียงราคาต่ำไปสูง):

| มาตรวัดทางสถิติ (Cutoff Rank $K = 3$) | ระบบค้นหาตามคีย์เวิร์ดทั่วไป (Baseline) | ระบบค้นหาอัจฉริยะ ISE (Multi-Criteria) | สรุปผลการประเมิน |
| :--- | :---: | :---: | :---: |
| **Precision@3** (ความแม่นยำใน 3 อันดับแรก) | **0.222** | **0.944** | **+325.2% สูงกว่าเดิมอย่างเห็นได้ชัด** |
| **Recall@3** (ความครอบคลุมสินค้าที่ตรงจริง) | **0.167** | **0.819** | **+390.4% ดึงสินค้าตรงสเปกได้ครบถ้วน** |
| **Mean Reciprocal Rank (MRR)** | **0.256** | **1.000** | **อันดับ 1 เป็นสินค้าที่ตรงตามสเปกทุกกรณี** |
| **Average Search Latency** (ความเร็วค้นหา) | $0.08\text{ ms}$ | $2.55\text{ ms}$ | ประมวลผลเสร็จในไม่กี่มิลลิวินาที |

> **ความโปร่งใสทางวิชาการ:** ค่า MRR = 1.000 และ Precision@3 = 0.944 ในการทดสอบนี้ หมายถึงอัลกอริทึมทำงานถูกต้องตามชุดทดสอบ Regression Test 6 ข้อ **ไม่ได้หมายความว่าระบบมีความแม่นยำ 100% กับทุกคำค้นหาในโลก** การประเมินในระดับ Production จะต้องเก็บข้อมูลคำค้นหาจริงจากผู้ใช้หลายพันคำเพื่อวัดค่า NDCG@K เพิ่มเติม

## 9. วิธีการเปิดใช้งาน (How to Run)

เนื่องจากระบบถูกสร้างด้วย Vanilla Web Technologies จึงสามารถเปิดใช้งานได้ทันทีโดยไม่ต้องติดตั้ง Build Tools:

### วิธีที่ 1: ดับเบิลคลิกเปิดใช้งานทันที
- ดับเบิลคลิกไฟล์ `index.html` เพื่อเปิดใช้งานบน Google Chrome, Microsoft Edge, Safari หรือ Firefox ได้โดยตรง

### วิธีที่ 2: รันผ่าน Local Web Server (แนะนำ)
```bash
# ใช้ Python (มีติดมากับเครื่องอยู่แล้ว)
python -m http.server 8000

# หรือใช้ Node.js npx serve
npx serve .
```
เปิดเบราว์เซอร์แล้วไปที่: `http://localhost:8000`

### วิธีที่ 3: รันชุดทดสอบ Benchmark ผ่าน Terminal
```bash
node -e "
const { ISE_PRODUCTS } = require('./data/products.js');
const { ISEQueryParser } = require('./js/engine/queryParser.js');
const { ISERetrievalEngine } = require('./js/engine/retrieval.js');
const { ISERankingEngine } = require('./js/engine/ranking.js');
const { ISEBenchmarkRunner } = require('./js/benchmark/benchmark.js');

const runner = new ISEBenchmarkRunner(ISE_PRODUCTS, ISEQueryParser, new ISERetrievalEngine(ISE_PRODUCTS), new ISERankingEngine());
console.log(runner.evaluate(3).summary);
"
```

## 10. สรุปโครงการ (Conclusion)

โปรเจกต์ **ISE** พิสูจน์ให้เห็นว่า การแก้ปัญหาการค้นหาและตัดสินใจซื้อสินค้าไอที **ไม่จำเป็นต้องพึ่งพา AI หรือโมเดล Machine Learning ขนาดใหญ่ที่กินทรัพยากรสูงเกินจำเป็น** 

เพียงใช้หลักการ **Information Retrieval (IR)** ที่ถูกต้อง ผสานระหว่าง:
1. การทำความเข้าใจความต้องการด้วย **Rule-Based Intent Parsing**
2. การคัดกรองด่วนด้วย **Inverted Index**
3. การตัดสินใจหลายมิติด้วย **Multi-Criteria Weighted Ranking**
4. การสร้างความน่าเชื่อถือด้วย **Explainable Reasoning**

ระบบก็สามารถช่วยให้ผู้ใช้งานทั่วไป ค้นพบสินค้าไอทีที่ตอบโจทย์การใช้งานจริงและงบประมาณได้อย่างแม่นยำ โปร่งใส และรวดเร็วในเสี้ยววินาที
