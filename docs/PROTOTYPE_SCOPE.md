# ISE Prototype Scope and Disclosure

เวอร์ชันเอกสาร: 1.0  
ตรวจทานล่าสุด: 8 กันยายน 2026

## วัตถุประสงค์

ISE เป็น University Capstone Prototype สำหรับพิสูจน์กระบวนการ:

```text
Search → Understand → Retrieve → Rank → Explain → Compare
```

กลุ่มเป้าหมายคือผู้ใช้ที่ทราบการใช้งานและงบประมาณ แต่ไม่จำเป็นต้องรู้ชื่อรุ่นหรือศัพท์ฮาร์ดแวร์ทั้งหมด

## ความสามารถปัจจุบัน

- วิเคราะห์คำค้นไทย/อังกฤษด้วยกฎและ Regular Expression
- แยก Category, Brand, Budget, Specs และ Use Case
- ตรวจคำค้นที่ไม่เกี่ยวข้องและคำค้นที่ต้องถามประเภทสินค้าเพิ่ม
- คัดเลือก Candidate ด้วย Inverted Index และ Constraint Filter
- จัดอันดับด้วย Active-criteria Multi-Criteria Ranking
- สร้างคำอธิบายจากสัญญาณคะแนนที่ระบบใช้จริง
- กรอง เรียงลำดับ ดูรายละเอียด และเปรียบเทียบสินค้าได้สูงสุด 3 รายการ
- รองรับ Desktop/Mobile และการใช้งานด้วย Keyboard ในเส้นทางหลัก
- มี Regression tests และ Benchmark 6 curated scenarios ที่ K = 3

## ข้อมูลที่ใช้

- ข้อมูลสาธิตแบบคงที่ 60 รายการใน 11 หมวด
- ไม่มีการเชื่อม Inventory ราคา หรือข้อมูลร้านค้าแบบ Real-time
- ราคาและสเปกเป็นค่าที่บันทึกไว้ในชุดข้อมูลและอาจไม่ใช่ข้อมูลปัจจุบัน
- ภาพ Placeholder เป็นภาพประกอบหมวดสินค้า ไม่ใช่ภาพถ่ายของรุ่นจริง
- คะแนน Programming, Gaming และ AI บางส่วนเป็นค่าที่ผู้จัดทำกำหนดเพื่อสาธิต Ranking

โปรดตรวจสอบราคา สเปก การรับประกัน และประสิทธิภาพกับผู้ผลิตหรือร้านค้าก่อนตัดสินใจจริง

## ข้อจำกัด

- รองรับคำศัพท์ คำพ้อง และรูปแบบภาษาที่อยู่ในขอบเขตกฎที่กำหนด
- อาจไม่เข้าใจคำสะกดผิดหรือภาษาพูดบางรูปแบบ
- ไม่รับประกัน FPS ประสิทธิภาพแบตเตอรี่ หรือผล Benchmark ของฮาร์ดแวร์จริง
- Match Score คือความตรงกับเงื่อนไขภายในระบบ ไม่ใช่ AI accuracy
- ผล Precision@3, Recall@3 และ MRR อ้างอิงเฉพาะ 6 curated scenarios และ Ground Truth ที่ผู้จัดทำกำหนด
- ยังไม่มีผล User Testing จริงจนกว่าจะดำเนินการตามแผนและบันทึกข้อมูลจากผู้เข้าร่วม

## สิ่งที่ไม่อยู่ในขอบเขต Prototype

- Backend และฐานข้อมูล Production
- Login, Cart, Payment และระบบสั่งซื้อ
- ราคาและสต็อกแบบ Real-time
- LLM, Vector Database และ Semantic Search
- Personalization จากประวัติผู้ใช้
- การรับประกันประสิทธิภาพเกมหรือฮาร์ดแวร์

## แนวทางพัฒนาระบบฉบับเต็ม

1. เพิ่มคำพ้อง การแก้คำสะกด และ Fuzzy Matching
2. เพิ่ม Semantic Retrieval และ Embedding ภายในโดเมนสินค้าไอที
3. เพิ่ม AI Intent Parsing ที่คืนข้อมูลตาม Schema และผ่าน Validation
4. เชื่อม Catalog ที่มีแหล่งข้อมูล Version และ Timestamp
5. ขยาย Benchmark ด้วยผู้ประเมินอิสระและคำค้นที่หลากหลาย
6. ทำ User Testing, Accessibility testing และ Cross-device testing

แนวทางเหล่านี้มีเป้าหมายเพื่อขยายความครอบคลุม ไม่ใช่รับประกันว่าระบบจะเข้าใจคำค้นทุกรูปแบบ

## ประโยคสำหรับใช้นำเสนอ

> Prototype นี้ไม่ได้อ้างว่าเข้าใจภาษาทุกรูปแบบ แต่พิสูจน์ Pipeline ตั้งแต่การแยกความต้องการ คัดเลือก จัดอันดับ อธิบายเหตุผล และจัดการคำค้นที่ไม่ชัดเจนได้อย่างตรวจสอบได้
